1. 现在哪儿坏了、不改会怎样

现在的插件只会管阅读清单，标签页一个都碰不了：你开着的 174 个标签页，助手只能读会话文件猜，没法替你分组或收起（U-DIAG-1）。不改的话，每多一种浏览器里的东西要整理，就得再写一个一次性插件。

核心概念

  • 能力开关：插件弹窗里的一个勾选框，管一类浏览器里的东西。例：勾上「标签页与标签组」，助手才能替你建分组；取消后，助手再调用会被插件当场拒绝。
  • 浏览器授权：Chrome 给插件的权限。例：第一次勾「历史记录」时 Chrome 弹窗问你「允许读取浏览历史吗」，你点拒绝，开关就弹回关闭。

页面示意

2. 要你拍的 0 件事

三件事你已在 2026-10-29 拍完，结论见第 7 节，这一页没有剩下要拍的事。

3. 撤不回来的与会变的

撤不回来的有两件，都要你当场点头。第一件是网上仓库改名（U-GATE-1）。第二件是改你本机的助手配置，让它每次都现问插件开了哪些能力，不再缓存一天（U-GATE-2）。改前会备份原配置。

会变的有六处。标签页能力的具体动作，包括关标签页前存备份，见（U-BEH-1），书签和历史的具体动作见（U-BEH-2）。插件多了一个弹窗；阅读清单的授权和现在一样装插件时就有，它的开关只管给不给助手用，另外三项勾选时才要授权（U-BEH-3）。开关变化会实时告诉助手，并记在本机，下次启动直接生效（U-BEH-4）。关着的能力，或授权已被你在浏览器设置里收回的能力，插件当场拒绝；新旧版本混着用时阅读清单照常能用（U-BEH-5）。名字和配置目录换新，旧目录自动搬过去（U-BEH-6）。

4. 代价、新增依赖与运维负担

没有新增依赖，只多一个插件弹窗页面和几项浏览器授权（U-DEP-1）。比不做贵在哪：未评估工时，[推断] 一轮单次开发就能做完，改动集中在服务和插件两处。

一期做完。五条验收都能当场测出来：

阅读清单照旧，读出来还是 368 条，老测试全过（U-ACC-1）。

6. 最可能翻车的假设

「标签页、书签、历史三项授权能等勾选时再要」已经查实：Chrome 官方文档列出的例外里没有它们，装上后勾选时会真的弹授权框再确认一次；阅读清单因为默认就开，授权改为装插件时就拿，和现在一样（U-SPK-1）。其次是「助手在会话中途能看到新开的能力」：接受风险，不行就新开一个会话，开关已记在本机（U-SPK-2）。最后是「改名后旧的安装地址还能用」：接受风险，改名当天同步改本机配置（U-SPK-3）。

7. 已定死不用你看的

你拍了三件事：在原仓库上直接改名（U-DEC-1）；新插件默认只开阅读清单（U-DEC-2）；助手能关标签页，关之前先存备份，也能按备份重新打开（U-DEC-3）。

阅读清单的六个工具名字和用法一个不改（U-CTR-1）。插件身份编号不变，不用重新配对（U-CTR-2）。只在本机通信、网页无法冒充插件这条安全线不动（U-CTR-3）。端口不变，新旧插件和服务混着用时阅读清单照常能用（U-CTR-4）。
